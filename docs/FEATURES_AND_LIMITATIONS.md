# MediLocker — Dashboard Modules, Capabilities & Honest Limitations

Status legend:
- **IMPLEMENTED**: Backed by real database persistence, backend endpoints, and UI integration.
- **PARTIAL**: Implemented with documented scope limits or local-only heuristics.
- **STANDALONE**: Exists as an independent script outside the web console.

---

| Module / Route | Status | Backend Support | What the User Can Do / See | Known Limitations |
|---|---|---|---|---|
| **Dashboard** (`/dashboard`) | **IMPLEMENTED** | `GET /api/dashboard/overview` | Release readiness (`NOT_RUN`..`BLOCKED`), first-run onboarding, 6 clickable metric cards (`Files`, `Records`, `PII`, `Clinical`, `Identity`, `Canary`), 6-stage workflow, Recent Jobs, Audit Events. | Metrics reflect jobs executed through the backend DB; independent CLI runs outside `backend/` do not populate the web DB. |
| **Datasets** (`/dashboard/datasets`) | **IMPLEMENTED** | `GET/POST /api/datasets`, `DELETE /api/datasets/{id}` | Upload `.csv`, `.tsv`, `.json`, `.jsonl`, `.txt`, `.pdf`, `.png` to an authorised organisation, trigger processing, poll live stage, download ZIP bundle, soft-delete. | Raw original patient records are never previewed in the browser. |
| **Privacy Engine** (`/dashboard/privacy-engine`) | **IMPLEMENTED** | `GET /api/jobs`, `GET /api/settings` | Inspect 5-stage pipeline, `RAKSHA_SECRET` status, and persistent job execution history. | Configuration changes via UI update SQLite `settings`; core `starter/config/policy.yaml` is used by the CLI engine. |
| **Privacy Intelligence** (`/dashboard/privacy-intelligence`) | **IMPLEMENTED** | `GET /api/privacy-intelligence`, `GET /api/privacy/assessments` | View measured PII counts, residual canary leaks, QI risk score, and release eligibility per job. | Shows `"Not measured"` until at least one job has completed. |
| **Attack Simulator** (`/dashboard/attack-simulator`) | **IMPLEMENTED** | `GET /api/threat-lab`, `POST /api/attack-simulator/run` | Execute deterministic 7-vector re-identification attacks (`simulate_attacks` in `starter/raksha_engine/attacker.py`) against any completed job. | Evaluates structural quasi-identifier combinations on processed `records.jsonl`; does not simulate external auxiliary commercial databases. |
| **Organisations** (`/dashboard/organisations`) | **IMPLEMENTED** | `GET/POST /api/organisations`, `GET /api/organisations/{id}/members` | View authorised organisations, types, regions, and contributed record counts; `PLATFORM_ADMIN` can create organisations. | Member invitation UI is not yet built in `/dashboard/organisations` (seeded/registered via API/DB). |
| **Identity Continuity** (`/dashboard/identity-continuity`) | **IMPLEMENTED** | `GET /api/identity/clusters` (`/api/identity-graph`) | Inspect pseudonymous patient clusters (`PSN-XXXXXX`), hospital source edges, precision/recall/F0.5, abstentions, and conflicts. | Raw names, Aadhaar, ABHA, and phone numbers are never displayed. |
| **Clinical Integrity** (`/dashboard/clinical-integrity`) | **IMPLEMENTED** | `GET /api/clinical/reports` | View exact preserved vs. expected clinical value numerators/denominators, modified/missing counts, and HL7 FHIR R4 validation status (`validate_fhir_r4_bundle`). | Evaluates numeric/unit clinical patterns and FHIR R4 JSON bundles; free-text semantic equivalence beyond unit/value tokens is not scored. |
| **Privacy Passports** (`/dashboard/privacy-passports`) | **IMPLEMENTED** | `GET /api/passports`, `POST /api/passports/{id}/verify`, `GET /api/passports/{id}/download` | View issued manifests, verify SHA-256 integrity hash, and download JSON or HTML passport reports. | Manifests are explicitly labelled `UNSIGNED` (SHA-256 hash-verified) because no asymmetric PKI signing key is provisioned. |
| **Research Network** (`/dashboard/research-network`) | **IMPLEMENTED** | `GET/POST /api/research/requests`, `POST .../approve`, `POST .../reject` | Submit collaboration requests (`SUBMITTED`) and approve/reject (`APPROVED`/`REJECTED`) based on RBAC. | Does **not** perform federated learning or secure multiparty computation; governs access to sanitised outputs only. |
| **Audit Trail** (`/dashboard/audit`) | **IMPLEMENTED** | `GET /api/audit/events` | Paginated append-only log of authentication, uploads, jobs, passport verifications, and settings updates. | Displays operational metadata only; never logs OTPs, secrets, or raw PII. |
| **Settings** (`/dashboard/settings`) | **IMPLEMENTED** | `GET/POST /api/settings` | View active user/role, SMTP & Google OAuth configuration status, and update output/quarantine policy settings. | SMTP and Google OAuth credentials must be configured via backend environment variables / `.env`. |
| **2-Page Project Brief PDF** (`generate_pdf.py`) | **STANDALONE** | None (CLI script) | Generates `starter/GuptKavach_Project_Brief.pdf` and `docs/GuptKavach_Project_Brief.pdf`. | Standalone ReportLab utility; not triggered from the web dashboard. |
